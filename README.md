## Установка

Нужны Docker и Docker Compose. Приложение — один контейнер; данные (БД SQLite, документы,
резервные копии) — в папке `data/` рядом с `docker-compose.yml`. Для ~10 сотрудников хватит
512 МБ памяти; место на диске — по объёму документов (до 25 МБ на файл).

Все команды выполняются в терминале из корня проекта.

### 1. Настройте файл окружения

Скопируйте `.env.example` в `.env`.

Первый администратор — задайте его логин и пароль (или создайте администратора командой
после запуска, см. [Команды администратора](#команды-администратора)):

- `INITIAL_ADMIN_LOGIN` — логин: латиница, цифры, точка, дефис.
- `INITIAL_ADMIN_PASSWORD` — пароль не короче 12 символов. При первом входе администратор
  сменит его на свой. Используется, только пока в системе нет ни одного сотрудника; после
  первого входа строку можно удалить из `.env`.

Остальные поля необязательные:

- `TRUST_PROXY` — адреса обратного прокси, которому приложение доверяет заголовки
  `X-Forwarded-For` (IP клиента) и `X-Forwarded-Proto`: через запятую, адреса или подсети,
  например `172.17.0.1` или `10.0.0.0/8`. `false` — приложение открыто напрямую, без прокси.
  Значение `true` («доверять всем») не принимается: тогда IP можно подделать и обойти лимит
  попыток входа. Подробнее — [HTTPS и обратный прокси](#https-и-обратный-прокси).
- `COOKIE_SECURE` — флаг Secure у cookie входа. `auto` — если запрос пришёл по HTTPS (за
  прокси — по `X-Forwarded-Proto`), `true` — всегда, `false` — никогда.
- `SESSION_IDLE_MINUTES` — через сколько минут без активности нужно войти заново (120).
- `SESSION_ABSOLUTE_HOURS` — через сколько часов после входа нужно войти заново, даже при
  активности (12).
- `BACKUP_TIME` — время ночной резервной копии, `ЧЧ:ММ` по Москве (`03:00`); `off` — не
  делать по расписанию.
- `BACKUP_KEEP` — сколько последних копий хранить (14).
- `BACKUP_DIR` — хранить копии не в `data/backups`, а в другом каталоге, см.
  [Резервные копии](#резервные-копии).
- `LOG_LEVEL` — уровень логов: fatal | error | warn | info | debug | trace | silent

### 2. Запустите приложение

```bash
docker compose up -d --build
```

Приложение доступно по адресу `http://<сервер>:9092`. Войдите под первым администратором и
заведите сотрудников в разделе **Сотрудники**: каждый получит временный пароль и при первом
входе задаст свой.

Проверить, что всё работает: `docker compose ps` показывает `healthy` (контейнер сам
опрашивает `/api/health`). Логи — `docker compose logs -f webmotiv` (JSON; паролей, токенов и
содержимого заказов в них нет).

Как устроен контейнер: приложение работает от пользователя `node`, без capabilities, корневая
файловая система только для чтения — писать можно только в `data/` (и `/tmp`). Логи Docker
ограничены ~50 МБ.

## HTTPS и обратный прокси

Приложение само HTTPS не обслуживает — его ставят за обратный прокси офиса (nginx, Traefik и
т. п.), который принимает HTTPS и передаёт запросы на порт 9092.

1. Если прокси на том же сервере, откройте порт только для него — в `docker-compose.yml`:
   `'127.0.0.1:9092:3000'` вместо `'9092:3000'`. Иначе порт доступен в сети в обход прокси.
2. В `.env` укажите `TRUST_PROXY` — адрес, с которого прокси приходит в контейнер. Для прокси
   на том же сервере это шлюз сети Docker:

   ```bash
   docker network inspect web-motiv_default -f '{{(index .IPAM.Config 0).Gateway}}'
   ```

   (имя сети — `<папка проекта>_default`). Проверка: после входа в разделе **Профиль →
   Сеансы** должен быть виден ваш настоящий IP, а не адрес прокси.

3. Прокси должен передавать `Host`, `X-Forwarded-For`, `X-Forwarded-Proto` и пропускать файлы
   до 25 МБ. Пример для nginx:

   ```nginx
   server {
       listen 443 ssl;
       server_name motiv.example.local;
       # ssl_certificate ...; ssl_certificate_key ...;

       # Документы — до 25 МБ; по умолчанию nginx режет запросы больше 1 МБ.
       client_max_body_size 26m;

       location / {
           proxy_pass http://127.0.0.1:9092;
           proxy_set_header Host $host;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```

Заголовки безопасности (CSP, HSTS, `nosniff` и др.) приложение ставит само — в прокси их
добавлять не нужно.

## Обновление

```bash
docker compose exec webmotiv webmotiv backup
git pull
docker compose up -d --build
```

Схема БД обновляется сама при запуске. Копия перед обновлением — чтобы можно было вернуться
(см. [восстановление](#восстановление)).

## Резервные копии

Каждую ночь в `BACKUP_TIME` приложение делает копию в `data/backups/<дата_время>/`:

- `app.sqlite` — согласованный снимок БД (делается на ходу, без остановки);
- `files/` — все загруженные документы.

Копия проверяется сразу после создания (целостность БД, все файлы на месте); хранятся
`BACKUP_KEEP` последних. Результат — в логах: «Резервная копия готова» или «Резервная копия
не удалась».

Документы после загрузки не меняются, поэтому в копиях они — жёсткие ссылки на файлы из
`data/files`: 14 копий занимают место примерно одной. Если `BACKUP_DIR` на другом диске,
файлы копируются.

**Копия на том же диске не спасёт при отказе диска или сервера.** Копируйте
`data/backups/` на другую машину своим средством резервного копирования; если копируете
вручную — с сохранением жёстких ссылок (`rsync -aH` или `tar`). Внутри копий — все данные
сервиса, храните их так же бережно, как сам сервер.

Хранить копии сразу на другом диске: смонтируйте его в контейнер и укажите каталог —
в `docker-compose.yml` в `volumes` добавьте `- /mnt/backup/webmotiv:/app/backups`, в `.env` —
`BACKUP_DIR=/app/backups`.

Сделать копию сейчас и посмотреть список:

```bash
docker compose exec webmotiv webmotiv backup
```

```bash
docker compose exec webmotiv webmotiv backups
```

### Восстановление

1. Остановите приложение:

   ```bash
   docker compose stop webmotiv
   ```

2. Восстановите нужную копию (имя — из списка `backups` или из `data/backups/`):

   ```bash
   docker compose run --rm webmotiv webmotiv restore 2026-10-04_030000
   ```

   Текущие данные не удаляются, а переносятся в `data/before-restore-<время>/`. Если
   приложение остановилось аварийно, команда попросит добавить `--force`.

3. Запустите приложение и проверьте, что данные на месте:

   ```bash
   docker compose start webmotiv
   ```

4. Когда убедитесь, что всё в порядке, удалите `data/before-restore-<время>/`.

Сеансы восстанавливаются вместе с БД, поэтому сотрудникам, скорее всего, не придётся входить
заново. Всё, что сделали после копии, теряется.

## Команды администратора

Создать администратора (спросит логин, ФИО и пароль):

```bash
docker compose exec webmotiv webmotiv create-admin
```

Выдать временный пароль сотруднику, который забыл свой (в том числе администратору):

```bash
docker compose exec webmotiv webmotiv reset-password <логин>
```

Список сотрудников и их ролей:

```bash
docker compose exec webmotiv webmotiv users
```

Резервные копии — `backup`, `backups`, `restore <копия>` (см. выше). Справка по всем
командам:

```bash
docker compose exec webmotiv webmotiv help
```

## Демо

Демо-данные: шесть сотрудников (администратор, два менеджера, бухгалтер, закупщик, склад), два
шаблона и десять заказов на разных этапах с документами. Демо добавляется только в базу без
этапов, шаблонов и заказов, так что в рабочие данные не попадёт; уже заведённые сотрудники
остаются.

Запустите приложение и выполните:

```bash
docker compose exec webmotiv webmotiv seed-demo
```

Команда напечатает логины и общий пароль. Начать демо заново — остановить приложение, удалить
`data/` и повторить.

## Для разработчиков

Нужен Node.js 22.18 или новее.

```bash
npm install
```

```bash
npm run dev
```

Фронт — `http://localhost:5173`, сервер — `http://localhost:3000`. Первого администратора
создайте командой `npm run cli -- create-admin`, а демо-данные — `npm run cli -- seed-demo`.

Перед коммитом — форматирование, линтер, типы, тесты и проверка зависимостей одной командой:

```bash
npm run check
```

После изменения схемы БД (`apps/server/src/db/schema.ts`) — сгенерировать миграцию:

```bash
npm run db:generate
```

До первого релиза миграции можно не копить: удалить `apps/server/drizzle/` и `data/`,
сгенерировать заново.

### Структура

- `apps/server` — сервер (Fastify, SQLite через Drizzle); `apps/server/demo` — документы для
  демо-заказов
- `apps/web` — интерфейс (React + Vite + Tailwind)
- `packages/shared` — общие схемы API, права, схема полей этапа
